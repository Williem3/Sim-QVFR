# Launcher settings inventory

Phase 1 of the UI overhaul (`OVERHAUL_PLAN.md`). This file lists every control, status and dialog the launcher shows today, so that each one gets a new place and nothing is lost. It was taken from `development` at `70fd3fe`.

## How the launcher draws its UI today

- **Framework:** none. The launcher draws its own UI with Win32, Direct2D and DirectWrite (`src/launcher/ui/`). It redraws the whole window every frame (immediate mode). Each pane is a function `*_pane(x, y, w, draw)` that returns its height. Controls register hit rectangles (`Hit`, `Ctl` ids in `window_state.h`). Keyboard focus follows `focus_order()` in `app_actions.cpp`.
- **Theme:** `theme_tokens.h`, generated by `tools/gen_launcher_theme.py` from `docs/qvfr-launcher-kit/qvfr-launcher-kit/tokens.json`. Light and dark follow the Windows app theme. The environment variable `SIM_QVFR_LAUNCHER_THEME=light|dark` forces one.
- **Layout today:** a game tab strip at the top, a 13-row sidebar in 5 groups (Setup, Picture, In the headset, Advanced, Help), a form column up to 760 px wide, a 300 px preview column (dropped under the form below 1000 px), and an action bar at the bottom (status, Restore Defaults, Launch). The window is 1160 × 740 by default and at least 880 × 600.
- **Saving:** every change is saved to `sim-qvfr.ini` straight away (`changed()` → `save_settings`). The live keys also go to a running game's copy (`push_live`). Each game keeps its own copy of the per-game keys (`switch_game_settings`). The ini is re-read every 500 ms, so a change made in the headset menu shows up here (`follow_ini`).

## Legend

- **Type:** toggle (a switch), slider, select (a popup or segmented control), button, text (a text field), info (read-only text, a badge or a readout), nav (moves between views).
- **Config key:** `[section] key` in `sim-qvfr.ini`, unless the row says otherwise. "—" means the control is not a setting.
- **Applies:**
  - **Live:** reaches a running game straight away.
  - **Live when lowered:** QVFR resolution is applied live up to the size the game launched with. Anything larger waits for the next launch.
  - **Next launch:** takes effect the next time the game starts.
  - **Launcher:** changes the launcher itself, not the game.
  - The card header badge today shows the first three (`form.cpp applies_tag`).
- **Per-game?:**
  - **Yes:** the key is in each game's settings copy and in profiles (`per_game_key`).
  - **No:** one value for every game.
  - **—:** not a setting.
- **New location:** `Tab › Card` in the new layout (see `OVERHAUL_PLAN.md`). The other places are:
  - **Rail:** the game rail on the left.
  - **Top bar:** the bar above the tab content.
  - **Profile menu:** the menu in the top bar.
  - **About sheet:** a dialog opened from the version in the rail.
  - **Report sheet:** a dialog opened from Game › Get help.
